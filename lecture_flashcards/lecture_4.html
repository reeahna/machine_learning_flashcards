MNIST Dataset & Binary Classification
▼
  • MNIST: 70,000 small images of handwritten digits (0–9) labeled with the digit they represent. A classic ML benchmark dataset.
  • Binary classifier: Distinguishes between just two classes. The "5-detector" example classifies each image as "5" or "not 5."
  • Why not use accuracy? Accuracy is misleading on skewed datasets. A "dumb" classifier that always predicts "not 5" gets ~90% accuracy because only ~10% of images are 5s. Precision and recall are better metrics.

Confusion Matrix — TP, FP, TN, FN
▼
  • Each row = actual class. Each column = predicted class.
  • True Positive (TP): Actually positive, predicted positive. ✓
  • True Negative (TN): Actually negative, predicted negative. ✓
  • False Positive (FP): Actually negative, predicted positive. ✗ (Type I error)
  • False Negative (FN): Actually positive, predicted negative. ✗ (Type II error)
Know all four cells

Precision, Recall & F1 Score — Equations
▼
  • Precision: Of all instances predicted positive, how many actually are? High precision = few false alarms.
  • Recall (Sensitivity / TPR): Of all actual positives, how many did we catch? High recall = few misses.
  • F1 Score: Harmonic mean of precision and recall. Only high if BOTH are high.
  • Precision/Recall trade-off: Increasing precision reduces recall and vice versa — you can't have both simultaneously at maximum.
Precision
Precision = TP / (TP + FP)
Recall (Sensitivity / TPR)
Recall = TP / (TP + FN)
F1 Score (harmonic mean)
F1 = 2 × (Precision × Recall) / (Precision + Recall) = TP / (TP + (FN + FP)/2)
All three equations — know them

ROC Curve & AUC
▼
  • ROC curve: Plots True Positive Rate (recall/sensitivity) vs. False Positive Rate (FPR) at all possible thresholds.
  • FPR: Ratio of negative instances incorrectly classified as positive. FPR = 1 − TNR (specificity).
  • TNR (Specificity): Ratio of negative instances correctly classified as negative.
  • ROC curve plots sensitivity vs. 1 − specificity.
  • AUC (Area Under Curve): Perfect classifier = AUC of 1. Random classifier = AUC of 0.5.
  • When to use PR vs ROC: Prefer PR curve when positive class is rare (skewed). ROC is fine when both classes are roughly balanced.

Multiclass: OvR vs. OvO
▼
  • One-versus-the-rest (OvR) / One-versus-all: Train one binary classifier per class (e.g. 10 for digits 0–9). Pick the class with highest confidence score. Used by SGD, Random Forest, Naive Bayes natively.
  • One-versus-one (OvO): Train a binary classifier for every pair of classes. For N classes: N×(N−1)/2 classifiers. Each classifier only needs data for its two classes — useful for algorithms that scale poorly with dataset size (like SVMs).
  • Strictly binary classifiers (Logistic Regression, SVMs) need OvR or OvO strategies for multiclass problems.
  • Multilabel classification: Outputs multiple binary labels simultaneously (e.g. face recognition — [Alice: yes, Bob: no, Charlie: yes]).
